# AUV 竞赛项目 · 成果佐证材料

> **本目录不包含 AUV 的任何源代码。**
> 该工程仍用于后续比赛，`Jetson_core_code/`、`tools/`、`ros_home/`、模型权重与完整原始录像均未上传。
> `.gitignore` 中对 AUV 的 `.py / .cpp / .h / .launch / .urdf / CMakeLists.txt` 等源码与工程文件设有显式拦截规则。

本目录是《Linux 基础及 ROS 应用实践》课程报告的进阶实践补充材料：一台自研 AUV 参加 **2026 年中国机器人大赛暨 RoboCup 机器人世界杯中国赛水下机器人赛项（水中巡游项目）** 的现场记录与分析结果。比赛水池 5 m × 10 m，规则要求机器人自主完全下潜、先撞指定颜色球，再完成过门、抓取/投放与返航；15 min 内最多三次尝试。

## 怎么读这些材料

1. **先看 `AUV_Project_Summary.md`**：它把"证据—纯策略—唯一控制写者—记录"四层分工、状态机迁移条件、HeadingGuard 与雷达/视觉门控讲清楚，并给出每张图对应的原始日志。
2. **再看 `figures/architecture.png` 与 `figures/mission_timeline_981ac8a2.png`**：前者是分层数据流，后者把一次真实下水的状态、深度、航向与请求画在同一时间轴上。
3. **最后对照 `logs/`**：`unit_test_final.log` 对应 35 项测试，`mission_demo.log` 对应 28.7 s 演示，`session_summary.txt` 汇总两次真实会话，`ball_track_selftest.log` 记录门控诊断。

## 如实声明

- **不宣称完整任务成功。** 981 会话最终停在 `LEFT`，31be 会话在航向修正处中止；两次都没有可用的 `ball_x` 或墙距样本，因此不能证明撞球或完整返航。
- **不以第一层证据替代第三层。** 纯策略测试只证明"给定观测，策略输出符合预期"，不证明飞控时序、推进器推力或水下通信；所有运动数值来自真实比赛日志、bag/视频回放或纯策略离线演示，不是赛后再次驱动推进器的结果。
- **参数存在版本漂移。** 演示参数副本仅把 `min_depth_m` 从 0.40 调到 0.20 以使 `start_depth_m=0.30` 通过校验；原始比赛参数文件未修改。
- **赛后复现条件受限。** `auv-final.service` 实测为 `inactive/disabled`，未连接 Pixhawk、推进器或相机硬件。

## 已知问题与下一步

1. `BallTrack` 的宽高比门控使用归一化坐标：16:9 画面中归一化宽高比 = 像素宽高比 × 0.5625，真实蓝球 0.306–0.425 全部被 0.5–2.0 的门控拒绝。修正方向是改为像素宽高比或可配置范围，并用 16:9 数据回归。
2. `Mission.validate()` 曾出现 `min_depth_m=0.40 > start_depth_m=0.30` 的冲突，需要把校验前置为下水前硬检查，并冻结现场参数版本。
3. 墙距有效性尚未接入 `/final/status`，"没有墙距时是否允许定时直行"需要显式策略。
4. 后续需完成雷达安装角/外参、压力零点、航向 PID、视觉阈值与推进器死区的系统标定。
